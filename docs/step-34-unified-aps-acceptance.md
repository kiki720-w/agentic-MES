# 第 34 步：Agentic MES 与 paichan 排产思路统一

## 产品收敛

本阶段停止把 Agentic MES 与 paichan 视为两个平行产品。Agentic MES 仓库成为统一制造运营产品，paichan 已在公司验证的排产思想作为 APS 领域能力进入同一生产事实、权限、审计和事件体系。

不迁入公司专用人员姓名、产品编码、账号、口令或生产数据。公开仓库只保存通用模型、算法、接口和模拟验收数据。

```text
工单 / 冻结工艺 / 设备状态 / 人员能力
                    ↓
      有限产能最早完工排产 V1
                    ↓
     排产明细 + 延期 + 未排能力缺口
                    ↓
       计划员提交 → 独立主管审批
                    ↓
              发布 / 撤回
                    ↓
         MES 执行事件驱动后续重排
```

## 已实现

- 通用 `PlanningResource`：人员或工作单元、工作中心、正常/加班能力、工序能力代码。
- 健康设备回退：没有人员能力档案时，直接读取同工作中心 `IDLE/RUNNING` 设备作为候选资源。
- 六工作日滚动日历：周一至周六生产、周日跳过，窗口可配置为 1–31 个工作日。
- 有限产能排产：按 MES 高优先级、交期、创建时间排序；同一工序选择能完整排入且最早完成的候选资源。
- 产品+工序或工序级标准工时覆盖；没有正式定额时使用生成请求中明确给出的默认工时，并把参数保存在计划版本中。
- 工艺顺序：同一工单的后续待排工序不能早于前序计划完成日。
- 透明缺口：暂停工单、能力不匹配、窗口产能不足都形成结构化 `shortages`，不静默丢单。
- 人工调整：计划员可在草稿阶段移动排产条目；目标日期、工作中心、工序能力和日能力上限由后端重新校验，原因与前后资源进入事件审计。
- 大样本工作台：产能日历按资源/日期汇总负荷，明细与缺口支持搜索及每页 50 项分页，能力资源列表限制可见数量，避免一次渲染全部记录。
- 计划治理：`DRAFT → PENDING_APPROVAL → APPROVED → PUBLISHED → WITHDRAWN`。
- Maker-Checker：计划创建/提交人与主管审批人必须不同，由领域层强制执行。
- 单车间只能发布一个当前计划；必须先撤回旧版本，再发布新版本。
- PostgreSQL 表、乐观版本、Outbox 制造事件和内存测试适配器。
- `/planning` 独立排产工作台，并从 MES 主控制台直接进入。

## 接口

- `POST/GET /api/v1/planning/resources`
- `POST /api/v1/planning/plans/generate`
- `GET /api/v1/planning/plans`
- `POST /api/v1/planning/plans/{planId}/assignments/{assignmentId}/move`
- `POST /api/v1/planning/plans/{planId}/submit`
- `POST /api/v1/planning/plans/{planId}/approve`
- `POST /api/v1/planning/plans/{planId}/publish`
- `POST /api/v1/planning/plans/{planId}/withdraw`

计划员负责资源、生成与提交；独立主管负责批准、发布和撤回。DeepSeek 不参与确定性排产计算、权限判断或发布。

## 与公司 paichan 的关系

吸收的已验证思想包括：人员能力匹配、正常/加班产能、滚动窗口、延期与未排缺口、人工计划调整思想、计划版本和审计。公司现有 paichan 继续运行，不在本阶段更改或迁移其生产数据库。

新内核以 MES 的工单、工序、设备和统一身份为事实源，不再复制第二份订单状态。后续接入公司环境时，应通过版本化适配器读取/映射现有 paichan 数据，并先进行影子排产对比，不能直接替换线上计划。

## 当前边界

- V1 是可解释的确定性启发式算法，不冒充数学最优解或 AI 自动排产。
- 当前分配一个主能力资源；人员与机床必须同时满足的双资源约束、刀具/夹具占用、物料齐套、换型矩阵、班次日历和维护窗口仍需下一阶段加入。
- 计划发布只形成受控执行版本，不会绕过 MES 工序状态机自动开机或派工。
- 默认工时只用于演示与缺少正式定额的显式场景；真实接入必须映射公司已确认的标准工时。

## 下一决策门

下一步是公司 paichan 的只读影子接入：定义版本化 `SchedulingSnapshot` 和 `ScheduleProposal` 契约，用同一批脱敏输入同时运行公司现行排产与统一 APS，比较任务覆盖率、产能违规、延期数和人员分配差异。只有对比通过后，才能讨论迁移或替换。
