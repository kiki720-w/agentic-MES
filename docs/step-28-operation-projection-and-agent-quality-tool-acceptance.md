# 第二十八步：工序投影巡检与Agent质量候选工具验收

结论：旧JSON工序与关系工序之间已有可在线调用的一致性巡检；质量Agent新增一个受车间范围约束、全程审计的R1只读工具。该工具只能读取已完工且尚未创建检验的候选工序，不能创建检验、修改生产数据或绕过人工权限。

## 在线一致性巡检

新增：

`GET /api/v1/system/operation-projection-health`

返回两种工序表示的总量、字段差异数和关系表额外记录数。PostgreSQL使用数据库内集合比较，不把全量数据加载到应用内存；其他存储适配器保留确定性的兼容实现。

状态规则：

- 数量相等、字段差异为0、额外记录为0时返回`CONSISTENT`。
- 任一条件不满足时返回`DRIFT_DETECTED`，可由部署监控据此告警。
- 巡检是只读操作，不自动覆盖任一侧数据，避免错误修复扩大数据损坏。

本机真实PostgreSQL在线结果：JSON工序63条、关系工序63条、字段差异0、额外记录0，状态为`CONSISTENT`。

## Agent只读质量候选工具

新增：

`POST /api/v1/agent-tools/list-quality-candidates`

工具契约：

- 工具名：`list_quality_candidates`。
- 风险等级：`R1`，敏感只读。
- 必填范围：`workshopId`，并限制单次读取1—100条。
- 授权：调用主体必须拥有目标车间读权限。
- 数据：仅返回该车间中状态为`COMPLETED`且不存在相同工单/工序检验记录的候选。
- 审计：允许和拒绝均写入`AgentToolCallRecorded`，包含Agent、主体、用途、工具版本、风险等级、策略结论和车间对象。

工具没有数据库连接能力，也没有创建检验的写接口。后续模型只能基于返回的最小结构化事实形成建议；真正的检验任务仍由质量业务服务、RBAC与人工流程控制。

## 验收结果

- Ruff通过。
- mypy通过，34个源文件无类型错误。
- 62项自动化测试通过，包含真实PostgreSQL投影比较。
- 车间范围内读取返回`ALLOW`，越权读取返回`DENY`并留下审计事件。
- 在线工具调用返回2条质量候选，风险等级为`R1`。
- 在线一致性巡检返回`CONSISTENT`，差异与额外记录均为0。

## 下一决策门

当前Agent只能被显式调用读取候选。下一步若启用`OperationCompleted`事件触发的自动质量分析，建议仍只生成去重的R2检验建议草稿，不直接创建检验；这一变化会引入主动Agent行为，需要单独确认。
