# 本地 AI 与云端业务系统的独立网络边界

2026-09-13，桌面 0.4.5。

CAPAXION 的本地模型可独立运行；客户使用云端 MES 不构成向云模型发送数据的授权。服务端分别配置模型和业务地址，前端选择服务商、提供密钥或改成 LOCAL/OLLAMA 标识都不能增加网络权限。

## 已实现

- 模型网关所有问答、诊断、连接验证与能力测评请求均受模型白名单限制。默认只允许 `http://127.0.0.1:11434/v1`，无云端回退。
- 厂内模型白名单使用明确的回环、RFC1918 或 IPv6 ULA 地址，不接受 DNS 名称和链路本地元数据地址。端口与 Base URL 路径必须匹配。
- 云模型需要单独登记 HTTPS Base URL。历史环境变量中的 DeepSeek 密钥不会自动授权云模型；未授权时启动状态为 BLOCKED，规则服务仍可运行。
- 本地模型支持无密钥连接。切换目的地址时不继承原服务密钥，配置厂内模型时不会自动取旧 DeepSeek 环境密钥。验证失败保留当前配置。
- 模型请求和新的业务读取组件均禁用环境代理与自动重定向。业务组件只支持受控相对路径 GET，没有通用代理接口或生产写入方法。
- 桌面“模型与数据边界”从服务端读取实际策略，显示独立白名单、云 MES 尚未接入，以及应用层限制的范围。

## 部署配置

以下变量在 Core 启动时读取，修改后需重启；逗号分隔多个完整 Base URL。空值表示没有授权。配置由部署管理员管理，模型设置页面不能修改白名单。

```dotenv
AUTONOMOUS_MES_MODEL_PROVIDER=LOCAL
AUTONOMOUS_MES_MODEL_NAME=your-installed-model-id
AUTONOMOUS_MES_MODEL_BASE_URL=http://127.0.0.1:11434/v1
AUTONOMOUS_MES_MODEL_API_KEY=
AUTONOMOUS_MES_MODEL_LOCAL_ENDPOINTS=http://127.0.0.1:11434/v1
AUTONOMOUS_MES_MODEL_CLOUD_ENDPOINTS=
AUTONOMOUS_MES_BUSINESS_ENDPOINTS=
```

客户选择具体云 MES 后，在 BUSINESS_ENDPOINTS 中登记其 HTTPS API Base URL，并开发相应认证、字段映射、分页、版本和同步逻辑。此操作不需要填写 MODEL_CLOUD_ENDPOINTS。厂内共享推理服务器可用例如 `http://192.168.10.20:8001/v1` 的明确地址；传输加密与访问控制按厂内部署要求配置。

## 实际验证与限制

132 项测试通过，5 项专用 PostgreSQL 测试因缺少隔离测试数据库跳过；Ruff、mypy、桌面构建通过。新增测试覆盖通道隔离、目的地址/路径/端口限制、禁止重定向、禁止代理、无密钥本地连接、密钥不跨地址沿用和历史云配置默认被阻止。

本机 Core 已切到官方 `Qwen3-8B-GGUF` 的 Q4_K_M 量化，模型 ID 为 `qwen3-8b-q4_k_m`。权重文件 SHA256 为 `d98cdcbd03e17ce47681435b5150e34c1417f50b5c0019dd560e4882c5745785`，与官方仓库 LFS 摘要一致；真实无密钥连接验证成功。服务只绑定 `127.0.0.1`，以离线模式运行，云模型出口仍关闭。

这里实现的是应用层目的地址边界，不是整机断网保证。模型进程自身、操作系统、身份服务与其他程序的网络行为不由这个组件控制；主机防火墙与部署网络审计仍需单独落实。HTTPS 云地址按名称匹配，DNS/IP 级出口控制由网络设施承担。

实际云 MES 连接器、断网后的重连同步、远端版本重校验与审批后回写尚未实现。本次没有连接真实云 MES、写入生产系统或授权新的云模型。已有签名入站接口保持原认证机制，业务出站白名单不会改变它的权限。

0.4.5 的七个桌面页面加载与六个可滚动页面检查通过，无脚本异常；真实《车工计划.xlsx》在打包程序中完成拖入、解析和人员能力预检。安装包：`desktop/release/CAPAXION-0.4.5-x64.exe`，SHA256：`F8AEABB78B98A0BC838DC317B5768368236077257DD0F9C7DDB8A53F9018BE96`。
