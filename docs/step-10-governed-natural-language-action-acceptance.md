# 第十步受控自然语言动作验收记录

日期：2026-09-12  
结论：首个自然语言动作“按明确工单号申请复工”已形成提案、审批和安全执行隔离闭环。

## 已实现

- 用户可输入“请恢复工单 WO-...”表达复工意图。
- 策略层在调用模型前识别写意图；缺少明确工单号时返回`REQUIRE_EXPLICIT_TARGET`。
- 系统只允许为当前`SUSPENDED`工单生成或复用`RESUME_OPERATION`提案。
- 对话响应返回`REQUIRE_APPROVAL`、提案编号、状态和证据引用。
- 对话接口本身不调用复工命令，不直接修改数据库中的工单状态。
- 实际复工继续使用已有审批端点；审批执行前重新校验设备健康、工单版本、权限原因和幂等键。
- DeepSeek 只负责诊断解释和建议文本，不拥有数据库连接、审批权限或生产控制工具。
- 未开放的派工、删除、设备控制等自然语言写指令继续被策略层拒绝。

## 实际验收

- 浏览器输入“请恢复工单 WO-INTERLOCK-8b13eb”。
- 页面返回`POLICY · deepseek-v4-flash · REQUIRE_APPROVAL`。
- 提案区显示`RESUME_OPERATION · PENDING_APPROVAL`及“审批执行”按钮。
- 未点击审批按钮；再次读取 PostgreSQL 后，工单仍为`SUSPENDED`且版本未变化。
- DeepSeek 不可用时仍可由规则内核形成安全结论，MES核心业务不依赖模型可用性。
- 全量自动测试：35项通过；Ruff和Mypy检查通过。

## 当前边界

这不是任意语言直接控制车间。当前只开放一个经过白名单定义的意图、一个明确目标类型和一个现有领域命令。后续每增加一种自然语言动作，都必须分别定义参数契约、风险等级、权限、审批条件、执行前检查、幂等规则、审计记录和回滚/补偿策略。
