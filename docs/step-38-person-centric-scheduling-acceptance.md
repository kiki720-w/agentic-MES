# 第 38 步：人员中心排产工作面验收

## 目标

让计划员不需要从资源明细中自行辨认人员，并确保所有产品页面都能直接进入 Agent 工作台。

## 已完成

- 控制塔、排产中心、排产结果、产能管理、Agent 工作台和离线模拟器均提供 `Agent 工作台` 入口。
- 各控制层页面统一显示 `当前身份`，并通过 `mes_dev_actor` 在页面之间保持选择。
- 身份外观与切换行为统一，但权限继续按计划员、主管和质量角色隔离，避免创建者自批或越权发布。
- 新增 `GET /api/v1/planning/input-summary`，从真实排产快照或演示投影返回工单、工序、人员/单元资源、工时覆盖和需求明细。
- 演示投影不再显示一组误导性的零值；缺失标准工时会明确标记为回退值，并按当前回退分钟预估需求分钟。
- 排产结果默认进入 `人员日排程`，逐行显示人员、日期、工单、工序、数量、分钟和当日负荷。
- 新增 `人员周计划`，按人员为行，固定保留六个工作日列（跳过周日并保留空白日），支持横向滚动查看任务卡和每日合计。
- 周计划仅保留表格底部原生滑动条；Agent 工作台增加输入区层次和间距，控制塔在中等宽度窗口自动切换为单栏，避免面板重叠。
- 工作单元与设备任务继续保留在全部工单明细和资源负荷中；没有 PERSON 任务时给出原因和产能管理入口。
- 每条新排产分配记录保存计算时采用的日容量，保证结果页可复核当时的负荷基准。

## 验收结果

- 核心与 API 契约测试：通过。
- PostgreSQL 集成测试：通过。
- Ruff 与 mypy：通过。
- 六个 HTML 页面脚本语法检查：通过。

## 产品口径

人员视图只展示 `PERSON` 类型资源。若某道工序只有 `CELL` 或设备产能，它不会被伪造为某位员工；计划员需先在产能管理中登记人员、工作中心和能力工序，再重新生成方案。
