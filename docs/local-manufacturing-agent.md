# Agent 主导的本地生产闭环

日期：2026-09-13。桌面版本：0.4.5。

CAPAXION 现在把 Agent 工作台作为制造任务主入口，同时保留产能管理、排产中心和排产结果作为人工检查与修改入口。模型负责把自然语言和非标准文件转换成候选业务动作；Core 负责字段校验、权限、版本、确定性排产、实际写入和回读核验。模型不会直接拼接 SQL。

## 人员能力表

工作台拖入 XLSX 后，会在本机查找“人员、加工种类、8 小时工时/日产能、加班工时/产能”一类表头。系统支持人员名单中常见的纵向合并与空白续行：同一人员的多项加工能力会合并，车工名单统一增加 `TURN` 工序能力，正常和加班产能分别取非空最大值。没有工号时按姓名生成稳定人员编号，因此再次导入会形成 `UPDATE` 或 `UNCHANGED`，不会重复新增。

预检接口为 `POST /api/v1/agent/imports/capacity/preview`。用户在对话中明确要求同步，或点击写入按钮后，`POST /api/v1/agent/imports/capacity/execute` 执行创建和版本化更新，再从产能管理回读每个资源。源文件、工作表、映射假设、跳过项、动作数和执行结果都会返回到工作台。缺少产能数值的人员会跳过并提示人工补录，其他有效人员仍可写入。

## 自然语言订单

用户可以直接给出物料、数量、交期、工序、单件工时和指定人员。`POST /api/v1/agent/tasks/execute` 先调用当前本地模型生成严格 JSON 动作；模型不可用时，常见中文字段由本地规则解析。Core 要求至少具备物料或工件名称、数量、交期、工序和工作中心，缺项时返回 `NEEDS_INFORMATION`，不会写入。

校验通过后，系统生成稳定工单号和幂等键，写入本地生产数据库并回读，然后运行有限产能排产。指定人员会作为排产硬约束；人员不存在或能力不匹配时，工单不会被写入。执行成功返回 `EXECUTED_AND_VERIFIED`，工作台可直接打开排产结果继续人工调整。

工作台会把最近 10 轮对话传给 Core，用于理解代词和追问。订单信息不足时，Agent 保留尚未写入的任务；下一句话可以只补充缺少的数量、交期或工时。用户说“取消”会清除待办且不写入生产数据。关键生产字段必须能在用户原始指令中找到，本地模型不能凭空补造后执行。

## 仍需现场配置的边界

当前人员能力适配器把车工表映射到 `WC-LATHE-01`，并把表中的工时数值作为分钟产能。两项规则都会在写入前显示，工厂应按自己的字段含义和工作中心编码调整。云端 MES 仍需要为客户系统实现独立连接器、身份认证、幂等写接口和回读接口；本地模型不需要访问互联网，只有该业务连接器需要访问云 MES 地址。
