# CAPAXION 工作台文档理解架构

工作台把“文件能力”和“模型能力”分开。文件拖入、格式校验、Excel/DOCX/PDF 解析、图片 OCR、文档保存、分块检索、字段映射、生产写入校验和写后回读均由本机 Core 执行。切换语言模型不会丢失这些能力。

## 当前数据流

1. Electron 只允许用户选择或拖入的文件进入上传通道，单文件上限 15 MB。
2. Core 在本机提取内容，为文件计算 SHA-256，并保存到 `.capaxion/documents`。
3. 文档被切成带工作表、页码或章节来源的片段。工作台提问时，Core 先检索最相关片段。
4. 使用本地模型时，相关片段只进入本地模型；图片至少经过本地 OCR。
5. 使用 DeepSeek 时，相关片段会发送到用户选择的 DeepSeek API；选择 `deepseek-v4-flash-vision-exp` 时，原始图片也作为视觉输入发送。
6. 回答返回实际使用的片段，工作台右侧“本次读取依据”显示文件名、位置和内容节选。

## 模型切换

工作台右上角可打开“模型与数据边界”。DeepSeek V4 Vision 预设使用：

- Base URL：`https://api.deepseek.com`
- 模型：`deepseek-v4-flash-vision-exp`
- API Key：由用户在本机界面输入，状态接口不会回显。

本地部署可以切换回 Ollama、LM Studio 或厂内 vLLM。只要模型提供 OpenAI Chat Completions 兼容接口，文档检索后的文本理解可直接复用；支持图像输入的模型还能接收原图，不支持视觉的模型仍使用 OCR 文字。

## 生产写入边界

模型负责理解意图和生成候选结构。人员能力导入、工单创建、排产、版本检查、权限检查、幂等控制和结果回读由 Core 工具完成。用户仍可在产能管理与排产结果页面检查和修改数据。
