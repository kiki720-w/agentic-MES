# ADR-0010：阶段一同步事务边界

状态：Accepted  
日期：2026-09-11  
取代：ADR-0002中“应用事务使用AsyncSession”的细节，其余决定不变。

## 决策

阶段一生产事务采用SQLAlchemy 2.0同步Session和psycopg 3同步驱动。FastAPI的同步路由由其线程池执行。设备长连接、模型调用和后台消费者保持独立I/O边界，不在生产数据库事务中等待外部服务。

## 理由

- 当前写入吞吐远低于数据库容量，正确的事务和并发控制优先于异步吞吐。
- 同步Session让工单、幂等记录和Outbox的原子提交更直接、易测试。
- 避免在领域服务全面异步化之前出现sync/async混用和共享Session风险。

## 复审条件

只有压测证明线程池或数据库等待成为瓶颈，才评估AsyncSession；迁移不得改变领域接口、API契约和Outbox语义。
