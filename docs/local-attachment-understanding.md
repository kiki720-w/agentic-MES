# 本地附件拖放与理解

日期：2026-09-13。桌面版本：0.4.5。

Agent 工作台现在接收整个 CAPAXION 窗口中的文件拖放。即使用户位于控制塔、排产或能力页面，拖入文件后也会自动进入 Agent 工作台。桌面壳使用 Electron `webUtils.getPathForFile` 读取本地文件；对于浏览器下载区等没有本地路径的虚拟文件，则读取拖放对象的字节内容，因此不会再把文件名或路径写进文字框。

## 本机解析范围

| 文件 | 本地处理方式 |
|---|---|
| TXT、Markdown、日志、JSON、YAML、XML | 编码识别、文字清理和有界提取 |
| CSV | 本地表格读取，同时尝试生产数据三表预检 |
| XLSX | Docling Slim 在本机识别工作表、合并单元格和连续数据区；Core 保留工作表名称、字段、样例和公平分配的有界节选；失败时回退到受列数限制的 `openpyxl` 提取 |
| DOCX | `python-docx` 提取段落和表格 |
| 文本型 PDF | `pypdf` 按页提取文字 |
| 扫描型 PDF | 对页面中的内嵌图片执行本地 RapidOCR |
| PNG、JPG、JPEG | RapidOCR + ONNX Runtime 本地 OCR |

解析成功后，附件卡片显示字符数。用户输入问题并发送时，提取内容会作为 `UNTRUSTED_USER_ATTACHMENT_DATA` 进入当前模型的只读事实区。附件中的文字不能授予权限、调用工具或执行生产动作。附件问答默认只使用附件内容，避免无关 MES 快照污染答案。

单次最多接收 8 个文件，每个文件不超过 15 MB；单文件最多保留 30000 个字符。针对当前 8192-token 本地模型，全部附件进入模型的文字合计限制为 1800 字符，并在附件间平均分配；结构化摘要优先，较长原文只作为剩余额度内的节选。原文件不上传外部文件服务。当前配置使用本地模型；如果未来允许云模型，模型出站策略仍由 Core 单独控制。

通用附件理解和生产写入计划是两个阶段。工作簿不是“工单、工序、产能”标准模板时，界面仍会显示已经识别的工作表与行数；人员能力适配器还会主动查找人员、加工种类和产能表头，形成可执行的资源新增或更新计划。用户在对话中明确提出同步或导入后，Core 执行写入并回读验证。无法形成唯一对象或安全字段映射的附件仍返回 `REQUIRE_FIELD_MAPPING`，不会猜测后写入。

附件会保持附加状态，用户可以连续追问或下达生产任务。文件中的文字始终只作为数据，不会被当成系统指令；真正的写入意图来自用户的对话指令或工作台动作按钮。

## 验证

- 单元和 API 测试覆盖 TXT、JSON、XLSX、DOCX、图片 OCR、扫描 PDF OCR、类型拒绝和附件不可信边界。
- Electron 端到端验证覆盖本地路径文件、无本地路径的虚拟文件、从非工作台页面拖入后自动跳转，以及拖入、解析、随问题发送、本地模型回答的完整链路。
- 真实测试 TXT 中的 `WO-FILE-713 / 37 件` 和测试图片中的 `M-27 / E-904` 均由本地模型准确回答。
- 《车工计划.xlsx》真实样本识别为 3 个工作表、367 个连续数据区和约 1337 个填充行；当前 Qwen3 8B 可结合本地解析结果回答具体人员、物料、日期与工时。
- 人员能力导入测试覆盖非标准工作簿识别、合并能力、稳定编号、重复导入、版本更新、写后回读和过期预检拒绝；自然语言订单覆盖本地模型解析、必填校验、指定人员约束、排产和模型故障降级。

便携包：`desktop/release/CAPAXION-0.4.5-x64.exe`，SHA256 为 `F8AEABB78B98A0BC838DC317B5768368236077257DD0F9C7DDB8A53F9018BE96`。界面左上角直接显示版本号，工作台始终显示“选择文件并在本机解析”入口；Windows 包声明 `asInvoker`，使其与普通权限的资源管理器处于相同权限级别。旧便携包移入 `desktop/release/archive`，发布目录顶层只保留当前版本。

图片 OCR 只理解可见文字。外观缺陷、表面质量、图纸尺寸关系、复杂表格结构和照片语义仍需要后续接入本地视觉模型并建立制造样本验收集。
