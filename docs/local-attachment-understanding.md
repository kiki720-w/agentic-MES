# 本地附件拖放与理解

日期：2026-09-13。桌面版本：0.4.3。

Agent 工作台现在接收整个 CAPAXION 窗口中的文件拖放。即使用户位于控制塔、排产或能力页面，拖入文件后也会自动进入 Agent 工作台。桌面壳使用 Electron `webUtils.getPathForFile` 读取本地文件；对于浏览器下载区等没有本地路径的虚拟文件，则读取拖放对象的字节内容，因此不会再把文件名或路径写进文字框。

## 本机解析范围

| 文件 | 本地处理方式 |
|---|---|
| TXT、Markdown、日志、JSON、YAML、XML | 编码识别、文字清理和有界提取 |
| CSV | 本地表格读取，同时尝试生产数据三表预检 |
| XLSX | Docling Slim 在本机识别工作表、合并单元格和连续数据区；Core 保留工作表名称、字段、样例和公平分配的有界节选；失败时回退到受列数限制的 `openpyxl` 提取 |
| DOCX | `python-docx` 提取段落和表格 |
| 文本型 PDF | `pypdf` 按页提取文字 |
| 扫描型 PDF | 对页面中的内嵌图片执行本地 RapidOCR |
| PNG、JPG、JPEG | RapidOCR + ONNX Runtime 本地 OCR |

解析成功后，附件卡片显示字符数。用户输入问题并发送时，提取内容会作为 `UNTRUSTED_USER_ATTACHMENT_DATA` 进入当前模型的只读事实区。附件中的文字不能授予权限、调用工具或执行生产动作。附件问答默认只使用附件内容，避免无关 MES 快照污染答案。

单次最多接收 8 个文件，每个文件不超过 15 MB；单文件最多保留 30000 个字符。针对当前 4096-token 本地模型，全部附件进入模型的文字合计限制为 1800 字符，并在附件间平均分配；结构化摘要优先，较长原文只作为剩余额度内的节选。原文件不上传外部文件服务。当前配置使用本地模型；如果未来允许云模型，模型出站策略仍由 Core 单独控制。

通用附件理解和 MES 写入预检是两种结果。工作簿不是“工单、工序、产能”标准模板时，界面仍会显示已经识别的工作表与行数，并说明需要字段映射；不会再把模板校验产生的 0 工单、0 工序、0 资源显示成文件解析结果。用户提出同步或导入时，缺少唯一业务主键、工序顺序或资源编号会返回 `REQUIRE_FIELD_MAPPING`，原附件继续保留在工作台，不会直接写入。

## 验证

- 单元和 API 测试覆盖 TXT、JSON、XLSX、DOCX、图片 OCR、扫描 PDF OCR、类型拒绝和附件不可信边界。
- Electron 端到端验证覆盖本地路径文件、无本地路径的虚拟文件、从非工作台页面拖入后自动跳转，以及拖入、解析、随问题发送、本地模型回答的完整链路。
- 真实测试 TXT 中的 `WO-FILE-713 / 37 件` 和测试图片中的 `M-27 / E-904` 均由本地模型准确回答。
- 《车工计划.xlsx》真实样本识别为 3 个工作表、367 个连续数据区和约 1337 个填充行；本地 Qwen3 4B 能回答具体人员、物料、日期与工时，模型网关保持 `VERIFIED`。
- 完整 Core 回归为 157 项通过、5 项因未配置隔离 PostgreSQL 测试库而跳过；Vite 构建通过。

便携包：`desktop/release/CAPAXION-0.4.3-x64.exe`。SHA256：`CBD381D97AC21A471872A3D5E989D6F269B6EC3ECA7D0C274E099D74A3B2604F`。界面左上角直接显示版本号，工作台始终显示“选择文件并在本机解析”入口；Windows 包声明 `asInvoker`，使其与普通权限的资源管理器处于相同权限级别。旧便携包移入 `desktop/release/archive`，发布目录顶层只保留当前版本。
