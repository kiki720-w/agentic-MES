# 第二十五步：十万工单与百万事件规模验证

结论：通过第一轮规模验证，并根据实测结果完成事件时间线索引和游标分页改造。

## 隔离与数据规模

- 数据库：现有本机PostgreSQL 17实例。
- 隔离方式：专用`agentic_mes_scale` schema，不连接生产API。
- 工单：100,000条。
- 制造事件：1,000,000条。
- 占用空间：约458 MB。
- 每个场景预热3次，采样30次。
- 生成脚本拒绝非`agentic_mes_scale*` schema，已有不匹配数据时拒绝覆盖。

| 场景 | P50 | P95 | 结论 |

## 由数据驱动的改造

- `list_outbox()`不再被页面调用，避免将全量事件加载到应用内存。
- `GET /api/v1/system/outbox`限制每次最多100条。
- 新增`nextCursor`，游标包含最后一条记录的`occurredAt + eventId`。
- 后续页使用严格小于游标的复合条件，保持稳定排序且不重复。
- 页面新增“加载更早”，逐批追加100条。
- 新增`ix_event_outbox_occurred_at_event_id`复合索引。
- API仍暂时保留offset兼容参数，但控制台不再使用深offset。

在百万事件下，游标P95约0.6ms，深offset约175ms，游标快约292倍，因此事件时间线正式选择游标方案。

## 可重复执行

```powershell
cd core
.\.venv\Scripts\python.exe scripts\scale-benchmark.py `
  --work-orders 100000 `
  --events 1000000 `
  --samples 30
```

脚本发现相同规模数据时直接复用；若行数不匹配则要求使用新的`agentic_mes_scale*` schema，不会清空已有数据。
